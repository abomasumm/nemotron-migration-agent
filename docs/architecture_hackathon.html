Nemotron migration agent

Point it at an old codebase. It pins current behaviour with tests, Nemotron Ultra plans the migration module by module, open models on Nebius Token Factory make the edits, and nothing merges until the tests stay green and a second model signs off. You make the final merge.

  • Nemotron on Token Factory
  • Open models on Token Factory
  • Dashboard
  • Scripts and you
  • Optional: Nebius Serverless

What changed from the current kit

  • Models: Claude Opus, OpenCode Go and GOAT are replaced by Nemotron Ultra, Super and Nano plus open models, all on Nebius Token Factory.
  • Harnesses: one hardwired harness becomes adapters, so each role can pick its own harness and model.
  • Tests: instead of tests that must fail first, characterization tests must pass on the old code and stay green after the migration.
  • Interface: a dashboard over the existing state files and logs replaces reading log files in the terminal.
  • Unchanged: the loop, worktrees, best-of-2 with a judge, gates, cross-model review and your final merge.
